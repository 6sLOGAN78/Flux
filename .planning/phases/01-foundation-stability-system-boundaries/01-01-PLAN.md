<threat_model>
## Assets
- Developer dependency graph, local database/Redis state, test credentials, and public error envelopes.

## Trust Boundaries
| Boundary | Risk |
|---|---|
| Lockfiles/tool manifests to downloaded binaries and packages | Dependency substitution or unreviewed version drift |
| Host to local containers | Services unintentionally exposed beyond loopback |
| Untrusted HTTP input to bind/validation helpers | Panic, cross-request data leakage, or diagnostic disclosure |

## Threats and Mitigations
| Threat ID | Category | Component | Disposition | Mitigation and verification |
|---|---|---|---|---|
| T-01-01 | Tampering | Toolchain and lockfiles | mitigate | Exact pins, one Bun lock, frozen install, and checksum-backed lock verification |
| T-01-02 | Information Disclosure | Validation errors | mitigate | Stable typed 400 response; tests assert raw binder text is absent |
| T-01-03 | Information Disclosure | Reused request values | mitigate | Per-request factories plus race tests with distinct payload markers |
| T-01-04 | Elevation of Privilege | Local Postgres/Redis | mitigate | Bind ports to 127.0.0.1 and use explicitly non-production credentials |
| T-01-SC | Tampering | Dependency supply chain | mitigate | Use audited/versioned sources, frozen lockfiles, and defer CI vulnerability enforcement to Plan 06 |

## Verification
Run the frozen install, `docker compose config`, focused race tests, and scan test responses for injected secret markers.

## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| HTTP input to log/span/metric fields | Attacker-controlled credentials, identifiers, paths and headers |
| Job payload/driver errors to telemetry | Private mail data, credentials and opaque provider messages |
| Process telemetry to collector/exporter | Remote service and monitoring-vendor transport |
## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information disclosure | All telemetry sinks | mitigate | Allowlisted sanitization before stdout/OTLP plus collector redaction and sentinel tests |
| T-05-02 | Spoofing | Request/job correlation | mitigate | Validate UUID/W3C metadata, replace invalid input, ignore baggage |
| T-05-03 | Denial of service | Metrics/export queues | mitigate | Fixed labels, bounded SDK queues/attributes, batching and export deadlines |
| T-05-04 | Repudiation | Asynchronous work | mitigate | Trace parent and correlation metadata persisted through existing queue retries |
| T-05-05 | Information disclosure | Monitoring destination | transfer | Vendor authentication/retention at collector deployment boundary; application exports safe OTLP only |
| T-05-SC | Tampering | Go telemetry modules/collector image | mitigate | Official exact release resolution, module checksums and image digest; no npm/pip/cargo installs |

Scope this register to the owned files in this plan; the remaining original boundary mitigations belong to the adjacent source-task fragments.
